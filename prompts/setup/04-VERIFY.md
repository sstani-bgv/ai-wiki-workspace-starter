# Этап 4. Проверка и передача

## Локальная проверка

Проверь реальные файлы, а не только намерение их создать:

- Корневые `AGENTS.md`, `CLAUDE.md`, `USER.md` и все части шаблона существуют.
- В новой системе `CLAUDE.md` содержит `@AGENTS.md`; сохранённые инструкции имеют
  согласованную маршрутизацию или её отсутствие явно отмечено.
- `USER.md` меньше 100 строк; в нём нет выдуманных или незаполненных данных.
- `wiki/index.md` ведёт к хабам, каждый хаб — ко всем страницам своей темы.
- Каждая содержательная страница ссылается на источник, связанные страницы и хаб.
- Локальные Markdown-ссылки разрешаются относительно файла, содержащего ссылку.
- Журнал отражает только реально выполненные действия.
- В реестре нет примера, выданного за реальный проект.
- Шаблоны проектов доступны, существующие проекты не изменены.
- В `.gitignore` исключены секреты и код дочерних проектов; шаблоны не исключены.

При ошибке исправь новые файлы, а изменения старых проведи по согласованной правке.
Проверь повторно. Если пользователь отказался менять старые файлы, честно перечисли
оставшиеся ограничения и не объявляй полную настройку завершённой.

## Передача

Назови абсолютный путь системы, покажи короткое дерево и список созданных/изменённых
файлов. Дай 2–3 примера запросов из README. Объясни, что будущий чат нужно открыть
в этой рабочей папке или явно попросить читать её инструкции.

Дай текст из [проверки нового чата](../VERIFY-WORKSPACE.md). Отдельно укажи:
локальные файлы проверены, независимая проверка новым чатом ещё предстоит.
Если она действительно выполнялась, приведи её результат и источники.

Временный пакет не нужен для дальнейшей работы. Не удаляй скачанные пользователем
файлы. Собственный временный клон можно оставить до завершения проверки; при
очистке удаляй только точно известный созданный тобой temp-каталог.
