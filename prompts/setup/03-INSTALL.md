# Этап 3. Создание системы

Работай в согласованной папке. Источник — `templates/workspace/` установочного пакета.

## Копирование

Копируй файлы поштучно, только если целевой путь отсутствует, включая проверку
симлинков. Не используй слепое рекурсивное копирование с перезаписью. Создай
недостающие каталоги. Не копируй корневые инструкции установочного пакета:
рабочий `AGENTS.md` берётся из `templates/workspace/AGENTS.md`.

Сохрани список созданных файлов. Шаблоны в `projects/_templates/` и
`projects/project-template.md` остаются шаблонами — поля в них заполняются только
при создании будущего проекта. Шаблоны не регистрируются как настоящие проекты.

## Профиль

Персонализируй только новый `USER.md`: имя, занятие, приоритеты, стиль работы,
границы и цель системы. Незнакомые значения — «Не указано». Держи файл меньше
100 строк. Существующий профиль меняй только после согласования конкретной правки.
Не создавай его дубликат в wiki. Сохраняй имя файла `USER.md`.

## Начальная wiki

Шаблон уже содержит тему `workspace` с источником и страницей об устройстве памяти.
Она полезна даже без личных ответов. Не меняй её правила на основе догадок.

Для подтверждённых ответов создай новый источник
`wiki/raw/workspace/YYYY-MM-DD-onboarding.md`: дату, вид «ответы пользователя при
настройке», краткую точную запись ответов и пропуски. Личные факты храни в `USER.md`,
в источнике достаточно согласованного краткого содержания без лишних подробностей. Добавь ссылку на
новую запись в `wiki/raw/workspace/README.md`; существующий хаб меняй только по
согласованной правке. Не заменяй старую запись с тем же именем: выбери свободное
имя с суффиксом или согласуй явное дополнение.

Из этого источника можно создать `wiki/pages/workspace/purpose.md` с целью и
направлениями системы, ссылками на `USER.md`, источник и страницу об устройстве
памяти. Добавь её в хаб темы и в индекс. Если эти файлы уже существовали, согласуй
точечные правки; при отказе сохрани новые страницы в inbox для разбора и сообщи о
незавершённом включении в индекс.

Создай дополнительные тематические хабы только для подтверждённых направлений.
Хаб может быть пустым и прямо говорить «Источников пока нет». Не придумывай
содержательное знание, страницы клиентов, историю решений и связи между ними.
Первое знание из интервью сохрани в raw, затем сделай одну страницу с источником,
свяжи её с хабом и индексом. Если пользователь его пропустил, достаточно темы
`workspace`. В `wiki/log.md` добавь фактическую запись о настройке; не переписывай
предыдущие записи.

## Общие инструкции

Для новой системы используй общий шаблон `AGENTS.md`, адаптированный из системы
автора. Предпочтения конкретного пользователя лежат в `USER.md`.
Новый `CLAUDE.md` должен содержать только `@AGENTS.md`.
Если инструкции уже существуют, покажи предложение точечного объединения без
потери действующих правил. При отказе сохрани исходные инструкции и сообщи,
какая часть маршрутизации осталась неподключённой.

## Проекты и Git

Оставь реестр пустым, если пользователь не дал данные для карточек. Не исследуй
существующие проекты и не создавай для них инструкции во время установки.
Git для личной системы необязателен. Если пользователь сам попросил Git, сначала
проверь существующее состояние, исключения для секретов и независимых проектов.
Не копируй Git-историю или remote публичного шаблона в личную систему.
